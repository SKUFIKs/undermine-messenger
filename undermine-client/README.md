# UnderMine Client

Веб-клиент криптографического мессенджера UnderMine: React + TypeScript + Tailwind CSS, с десктопной сборкой через Electron.

---

## Технологии

- **React 18 + TypeScript** — UI
- **Vite** — сборка и dev-сервер
- **Tailwind CSS 4** — стилизация
- **Electron** — десктопное приложение
- **@noble/curves + @noble/ciphers** — E2EE криптография (Curve25519 ECDH + ChaCha20-Poly1305 AEAD)

---

## Возможности

- **Авторизация и регистрация** — через HTTP API сервера (`/api/v1/auth/register`, `/api/v1/auth/login`)
- **Персистентные сессии** — токен и ключевая пара сохраняются в `localStorage`, вход не требуется после каждого перезапуска приложения
- **Обмен сообщениями в реальном времени** — через WebSocket (`/ws`)
- **Сквозное шифрование (E2EE)** — Curve25519 (ECDH) + ChaCha20-Poly1305 AEAD; сервер не видит содержимого сообщений
- **Стабильные ключи аккаунта** — ключевая пара генерируется один раз и персистится в `localStorage`, поэтому перелогин и перезапуск не ломают шифрование
- **Персистентная история чатов** — чаты и сообщения сохраняются в `localStorage` и восстанавливаются после перезапуска приложения
- **Групповые чаты** — создание групп, управление участниками, групповые сообщения с общим ключом группы (зашифрованным для каждого участника через pairwise-ключ)
- **Офлайн-доставка сообщений** — автоматическое получение отложенных пакетов при переподключении
- **Авто-переподключение WebSocket** — с экспоненциальным бэкоффом (1с → 15с)
- **Всплывающие уведомления (toast)** — информирование о событиях соединения, ошибках отправки, операциях с группами
- **Поиск контактов** — поиск по имени пользователя в каталоге публичных ключей
- **Сплит-режим (dual view)** — одновременная симуляция двух клиентов в одном окне для тестирования шифрования
- **Защита от сообщений самому себе** — отправка в собственный чат заблокирована
- **Дедупликация сообщений** — повторная доставка офлайн-очереди не создаёт дубликатов

## Конфигурация

Все параметры задаются через `.env` файл (загружается и в dev-режиме через Vite, и в Electron через `dotenv`):

| Переменная | По умолчанию | Описание |
|------------|--------------|----------|
| `VITE_SERVER_URL` | `http://localhost:8080` | URL бэкенда (Go-сервер или Node-ретранслятор) — все API и WebSocket идут на этот адрес |
| `VITE_HOST` | `0.0.0.0` | Хост Vite dev-сервера |
| `VITE_PORT` | `5173` | Порт Vite dev-сервера (не должен конфликтовать с портом бэкенда) |
| `ELECTRON_DEV_URL` | *(пусто)* | URL страницы для Electron в dev-режиме; пусто = `http://localhost:VITE_PORT` |
| `ELECTRON_WINDOW_WIDTH` | `1100` | Ширина окна Electron |
| `ELECTRON_WINDOW_HEIGHT` | `740` | Высота окна Electron |
| `ELECTRON_WINDOW_MIN_WIDTH` | `840` | Минимальная ширина окна |
| `ELECTRON_WINDOW_MIN_HEIGHT` | `540` | Минимальная высота окна |

```bash
cp .env.example .env
```

## Скрипты

| Команда | Описание |
|---------|----------|
| `npm run dev` | Запуск Node-ретранслятора (`server.ts`) — порт 8080, отдаёт UI и проксирует API/WS на Go-сервер |
| `npm run build` | Продакшен-сборка фронтенда в `dist/` |
| `npm run preview` | Предпросмотр собранного фронтенда |
| `npm run lint` | Проверка типов (`tsc --noEmit`) |
| `npm run electron` | Запуск десктопного приложения (Electron) |
| `npm run build:exe` | Сборка портативного `.exe` через electron-builder (Windows) |

## Запуск

Требуется **Node.js 20+**.

### Режим разработки (фронтенд + Node-ретранслятор)

```bash
npm install
npm run dev
```

Откройте `http://localhost:8080` — Node-ретранслятор отдаёт собранный UI и проксирует `/api` и `/ws` на Go-сервер (адрес из `VITE_SERVER_URL`).

### Режим разработки (только фронтенд через Vite)

```bash
npm install
npx vite
```

Vite dev-сервер на `http://localhost:5173` проксирует `/api` и `/ws` на `VITE_SERVER_URL`.

### Десктопное приложение

```bash
npm install
npm run electron
```

### Сборка исполняемого файла

```bash
npm run build:exe
```

Результат — `release/UnderMine 1.0.0.exe` (портативный, без установщика).

## Как это работает

### Личные сообщения

1. **Регистрация** — клиент генерирует ключевую пару Curve25519, отправляет публичный ключ на сервер, приватный ключ остаётся только в `localStorage` браузера.
2. **Вход** — клиент загружает сохранённую ключевую пару (или создаёт новую при первом входе) и регистрирует публичный ключ на сервере.
3. **Начало чата** — при выборе собеседника клиент вычисляет общий секрет через ECDH (Curve25519) и кеширует его.
4. **Отправка** — сообщение шифруется ChaCha20-Poly1305 общим ключом и отправляется на сервер в бинарном пакете `0x01`.
5. **Получение** — получатель пробует кешированные общие ключи; если ключ не найден (например, после перезапуска), клиент запрашивает каталог пользователей и вычисляет ключ заново.
6. **Офлайн** — если получатель не в сети, сервер хранит сообщение в очереди и доставляет при подключении.

### Групповые сообщения

1. **Создание группы** — владелец генерирует случайный групповой ключ (32 байта), шифрует его для каждого участника через pairwise-ключ (ECDH) и загружает на сервер.
2. **Загрузка ключа** — при входе участник забирает свой зашифрованный ключ с сервера и расшифровывает его pairwise-ключом с владельцем группы.
3. **Отправка** — сообщение шифруется групповым ключом и отправляется в пакете `0x05` с указанием отправителя и группы.
4. **Получение** — участники расшифровывают сообщение групповым ключом.
5. **Управление** — владелец может добавлять/удалять участников; при добавлении нового участника групповой ключ шифруется для него и загружается на сервер.

### Сессии

- Сессия (токен, userId, ключевая пара) хранится в `localStorage` и переживает перезапуск приложения.
- При восстановлении сессии клиент синхронизирует публичный ключ с сервером.
- Если токен больше не валиден (например, БД сервера была пересоздана), клиент автоматически разлогинивается и показывает уведомление.
