# UnderMine Desktop Client (Go + Fyne v2)

Десктопный клиент мессенджера UnderMine на **Go (1.22+)** и **Fyne v2.6+**.

## Возможности

- **Авторизация и регистрация** — через HTTP API сервера
- **Обмен сообщениями в реальном времени** — через WebSocket
- **Сквозное шифрование (E2EE)** — Curve25519 + ChaCha20-Poly1305
- **Офлайн-доставка сообщений** — сервер сохраняет сообщения для офлайн-пользователей
- **Поиск контактов** — по имени пользователя

## Архитектура

```
undermine-messenger/
├── cmd/client/main.go              # Точка входа, связывает UI с бизнес-логикой
├── internal/

│   ├── app/router.go               # Навигация между экранами
│   ├── client/
│   │   ├── crypto.go               # Криптография (Curve25519, ChaCha20-Poly1305)
│   │   ├── network.go              # WebSocket клиент
│   │   ├── ping.go                 # Пинг-механизм
│   │   └── state.go                # Состояние приложения
│   ├── domain/                     # Модели данных
│   ├── protocol/                   # Протокол обмена пакетами
│   └── ui/                         # Интерфейс (Fyne)
│       ├── components/             # Переиспользуемые виджеты
│       ├── theme/                  # Кастомная тема
│       └── views/                  # Экраны (авторизация, чат)
├── .env                            # Конфигурация (адрес сервера)

├── go.sum
└── Makefile
```

## Конфигурация

Клиент читает адрес сервера из файла `.env` в корне проекта:

```env
SERVER_URL=http://localhost:8080
```

Если файл `.env` отсутствует, клиент запросит адрес сервера в поле ввода на экране авторизации.

## Запуск

### Предварительные требования

- Go 1.22 или выше
- Сервер UnderMine запущен (см. `undermine-server/README.md`)

### Сборка и запуск

```bash
# Сборка
go build -o client ./cmd/client/main.go

# Запуск
./client
```

Или через Makefile:

```bash
make build
make run
```

## Использование

1. Запустите сервер (`undermine-server`)
2. Запустите клиент
3. Введите адрес сервера (или он будет загружен из `.env`)
4. Зарегистрируйтесь или войдите
5. Найдите контакт по имени пользователя
6. Начните общение

## Безопасность

- Закрытые ключи генерируются на клиенте и никогда не покидают устройство
- Сообщения шифруются алгоритмом ChaCha20-Poly1305
- Обмен ключами осуществляется через Curve25519 (ECDH)
- Сервер не имеет доступа к содержимому сообщений (Zero-Knowledge Relay)
