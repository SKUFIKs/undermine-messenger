# UnderMine Messenger

Криптографический мессенджер с архитектурой **Zero-Knowledge Relay** и сквозным шифрованием **E2EE** (Curve25519 ECDH + ChaCha20-Poly1305 AEAD).

Сервер не хранит закрытые ключи и не имеет доступа к содержимому сообщений. Все сообщения шифруются только на клиентах.

## Возможности

- **Сквозное шифрование (E2EE)** — генерация ключевой пары Curve25519 на клиенте, общий секрет через ECDH, шифрование ChaCha20-Poly1305 AEAD. Приватные ключи никогда не покидают клиента.
- **Zero-Knowledge Relay** — бэкенд маршрутизирует только зашифрованные бинарные пакеты, не видит ключи и не расшифровывает содержимое.
- **Личные и групповые чаты** — групповой ключ генерируется владельцем, шифруется pairwise-ключами для каждого участника и хранится на сервере в зашифрованном виде.
- **Офлайн-доставка** — сообщения офлайн-получателям сохраняются в очереди и доставляются при подключении.
- **WebSocket в реальном времени** — двусторонний обмен сообщениями с подтверждением доставки.
- **Персистентные сессии и история** — токен сессии, ключевая пара и история чатов сохраняются в `localStorage` (клиент).
- **Автопереподключение** — WebSocket переподключается с экспоненциальным бэкоффом.
- **Десктоп-версия** — сборка в портативный `.exe` через Electron.

## Структура проекта

- **`undermine-server/`** — Бэкенд на **Go 1.21+** (HTTP REST API + WebSocket Relay). См. подробности в [undermine-server/README.md](./undermine-server/README.md).
- **`undermine-client/`** — Веб-клиент на **React + TypeScript + Vite + Tailwind CSS**. Есть dev-прокси/ретранслятор на Node (Express + WS), а также десктоп-сборка через Electron. См. [undermine-client/README.md](./undermine-client/README.md).

## Требования

- **Go** 1.21+ (для сервера)
- **Node.js** 20+ (для клиента)
- **npm** (или совместимый пакетный менеджер)

## Быстрый запуск

Проект можно запускать в двух частях: бэкенд (Go) и клиент (Node/Vite/Electron).

### 1. Запустить сервер (Go)

```bash
cd undermine-server

# Скопировать конфиг (опционально)
cp .env.example .env

# Запуск без сборки
go run ./cmd/server

# Или собрать и запустить
go build -o server ./cmd/server/main.go
./server
```

Сервер по умолчанию доступен на `http://localhost:8080`.

### 2. Запустить клиент (web)

Есть два варианта:

**Вариант A. Через встроенный ретранслятор (рекомендуется для dev, UI на порту 8080):**

```bash
# Из корня репозитория
npm install
npm run dev
```

Откройте `http://localhost:8080` — Node-ретранслятор (`undermine-client/server.ts`) отдаст фронтенд и проксирует `/api/*` и `/ws` на Go-сервер (берёт URL из `VITE_SERVER_URL`).

**Вариант B. Отдельно Vite dev-сервер (порт 5173):**

```bash
cd undermine-client
npm install
npx vite
```

Откройте `http://localhost:5173`. Vite проксирует API/WS на адрес из `.env` (`VITE_SERVER_URL`).

## Конфигурация

### Сервер (`undermine-server/.env`)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `PORT` | `8080` | Порт HTTP/WebSocket сервера |
| `HOST` | `0.0.0.0` | Адрес прослушивания |

### Клиент (`undermine-client/.env`)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `VITE_SERVER_URL` | `http://localhost:8080` | URL Go-сервера (API + WebSocket) |
| `VITE_HOST` | `0.0.0.0` | Хост Vite dev-сервера |
| `VITE_PORT` | `5173` | Порт Vite dev-сервера |
| `ELECTRON_DEV_URL` | *(пусто)* | URL для Electron в dev-режиме (по умолчанию `http://localhost:${VITE_PORT}`) |
| `ELECTRON_WINDOW_WIDTH` | `1100` | Ширина окна Electron |
| `ELECTRON_WINDOW_HEIGHT` | `740` | Высота окна Electron |
| `ELECTRON_WINDOW_MIN_WIDTH` | `840` | Минимальная ширина окна |
| `ELECTRON_WINDOW_MIN_HEIGHT` | `540` | Минимальная высота окна |

## Основные принципы безопасности

- **Никаких закрытых ключей на сервере.** Ключевая пара Curve25519 генерируется на клиенте, приватный ключ хранится только в `localStorage`.
- **Сообщения не расшифровываются сервером.** Весь трафик полезной нагрузки — зашифрованный бинарный пакет (AEAD).
- **Групповые ключи в зашифрованном виде.** Общий ключ группы шифруется pairwise (ECDH) для каждого участника, сервер хранит только зашифрованные версии.
- **Хеширование сессий.** Сессионные токены на Go-сервере хранятся в виде SHA-256 хэша.
- **Хранение паролей.** Пароли хэшируются (bcrypt на Go-сервере, SHA-256 с солью во встроенном ретрансляторе `server.ts`).
- **Zero-Knowledge по дизайну.** Серверу известны только идентификаторы пользователей, структуры доставки и метаданные соединений — не содержимое переписок.
